# /conclude — 把一次问答存成笔记

用户发 `/conclude` 后，把**指定那一问一答**整理成 Markdown 文件，写到他指定的位置。

默认行为：序号省略 → 取本会话最后一个「真问题」；地址省略 → 写进下面「配置」里的笔记仓库根目录；分隔符决定合并还是分开（见「参数解析」）。

> 配套：本 skill 与 `list-questions` 配合——编号以最近一次 `/list` 的表为准。单独使用也成立：本会话没出过表时，按同一套规则现场重建。

## 配置（安装后改这一处）

默认仓库：`<在这里填写你的笔记库绝对路径，例如 D:\obsidian-vault>`

- 填了：地址省略时写进这个目录
- 没填：地址省略时**不要猜路径**，直接回一句「请告诉我存到哪个目录」，并附上本会话的提问表

## 触发条件

- 行首是 `/conclude`（大小写都算）
- 正文里提到 "/conclude" 不算
- 消息**同时包含** `/conclude` 和别的内容时，按本文件解析；不要把它当成普通提问去回答

## 参数解析

去掉 `/conclude` 后，按顺序拆：

1. 取开头连续的**数字 token**；数字之后（第一个非数字 token 起）的内容当**地址**（引号包起来的，去掉引号）。
2. **分隔符决定合并方式**：
   - **逗号 / 短横**分隔（`6,7,8`、`2,4-6`、`1-3`）→ **分开模式**：一个问题一个文件。
   - **空格**分隔（`6 7 8`）→ **合并模式**：这几个问答合成一篇文件。
   - 单个数字（`3`）→ 单篇，无合并/分开之说。
3. 开头不是数字 → 整段都当地址，序号取默认（最后一个真问题）。

例子：

| 输入 | 序号 | 模式 | 地址 |
|---|---|---|---|
| `/conclude` | 最后一个真问题 | 单篇 | 默认 |
| `/conclude 3` | Q3 | 单篇 | 默认 |
| `/conclude 2,4-6` | Q2、Q4、Q5、Q6 | 分开（4 篇） | 默认 |
| `/conclude 6 7 8` | Q6、Q7、Q8 | 合并（1 篇） | 默认 |
| `/conclude 2,4-6 我的笔记` | Q2、Q4、Q5、Q6 | 分开（4 篇） | `<仓库>\我的笔记` |
| `/conclude "D:\notes\ 学习"` | 最后一个真问题 | 单篇 | `D:\notes\学习` |
| `/conclude 3 我的笔记` | Q3 | 单篇 | `<仓库>\我的笔记` |

## 序号从哪来

**以本会话最近一次 `/list` 输出的表为准**，不重新数。

- 本会话还没出过 `/list` 的表 → 按 `list-questions` 的同一套规则现场生成一张，开头说明一句「本会话还没 /list，我按同样规则重建了编号」
- 用户给的号在表里不存在 → **报错，并把当前表重新贴一遍**，不要猜他想存哪条
- 表生成之后他又问了新问题 → 仍然按表来，不重排；若他给的号越界，按上一条处理

「真问题」的定义与 `/list` 一致：真在问「是什么 / 为什么 / 怎么做 / 能不能 / 有什么区别」的句子。跳过：纯操作指令（「存进去」「改一下」）、补充陈述、确认句（「对」「好」）、`/list` 与 `/conclude` 本身。

## 内容怎么写

**忠实整理**：结构不动，只去水词。

### 保留

- 原回答的小标题层级、代码块、表格、列表、命令行
- 结论、数字、路径、版本号、文件名
- 原回答里已有的 `[已验证]` `[未验证]` `[推测]` 之类标记
- 关键的判断依据（一句就够，不要删成只有一个光秃秃的结论）

### 删除

- 开场白：「好的」「我来帮你」「以下是」
- 收尾：「希望对你有帮助」「还需要什么随时说」
- 重复啰嗦的过渡句
- 与这一问一答无关的旁枝

### 禁止

- 不新增事实、不改数字、不改结论
- 不把「我没验证」整理成「确认了」
- 不追加你自己的评价和建议
- 不把长回答压成几条要点（那是「提炼」，用户明确不要）

一般压到原回答的 50%–80%。

### 文件模板

单篇（或分开模式的每一篇）：

```markdown
---
date: 2026-10-24
---

# {问题}

> 提问原文：{用户当时的原话}
> 来源：{YYYY-MM-DD 的会话}

## 回答

{整理后的回答}

## 本轮动过的文件

- `C:\path\to\x.md`（新建）
- `D:\vault\我的笔记\y.md`（修改）
```

「本轮动过的文件」只在那一轮确实动过文件时才写；没有就整节删掉，不要留空标题。

**合并模式**：不是把几问平铺，而是整合成一篇连贯的文章。整篇只写一个 frontmatter，标题取能概括这几问共性的那一句，正文按「一句话结论 → 为什么 → 好处/代价 → 怎么选」重组：

```markdown
---
date: 2026-10-25
---

# {能概括这几问的标题}

> 来源：{YYYY-MM-DD 的会话}（Q6–Q8 整合）

## 一句话结论

...

## 为什么

...

## 好处 / 代价

...

## 怎么选

...
```

仍保留原回答的结论、数字、代码块与易错点，但不重复几问共有的内容。

frontmatter **只写 `date`**，不打 tags —— 没有事先约定的标签体系时不要临时造新词。

## 写到哪

判定顺序（`<仓库>` 指「配置」里那个目录）：

1. 没给地址 → `<仓库>\{问题}.md`（合并模式用「合并文件名」）
2. 给了以盘符开头的绝对路径（或 `/` 开头的 POSIX 路径）→ 直接用；若指向的是目录，文件放进去
3. 给了 `.md` 结尾的路径 → 把它当完整文件名
4. 给了别的相对名（如 `我的笔记`、`AI写入/周总结`）→ 接到仓库根后面

路径不存在时**自己建目录**，不要因为目录没建好就放弃。

### 要不要先问

- **笔记仓库内部**（含任何子目录）→ 直接写，不问。用户敲 `/conclude` 本身就是授权。
- **仓库外部**（其他盘、系统目录等）→ **先说明「要写到 X，为什么」再等确认**，确认后才动手。用户只说 `/conclude` 时，授权范围就是那个仓库。

## 文件名

- 用表格里「问题」那一列的文字，去掉句末标点
- **合并模式**：文件名用「第一个问题的标题」+「等N问」，例：`为什么要用 code 定义数组等3问.md`
- 各系统不允许的字符 `/ \ : * ? " < > |` → 换成 `-`
- 去掉首尾空格；连续多个短横合并成一个
- 超过 60 个字符就从后面截断（留完整词，别把字切一半）

## 同名冲突

写之前先看文件在不在。

**已存在 → 停下来问**：「`{路径}` 已经存在，覆盖 / 新建为 `{名}-2` / 跳过？」

不许自己决定覆盖。用户选了哪个就执行哪个。

## 批量

序号支持两种分隔，行为不同：

- **分开**：`/conclude 1,3,5`、`/conclude 1-3`、`/conclude 1-3,7`（逗号/短横）→ **一个问题一个文件**。
- **合并**：`/conclude 6 7 8`（**空格**）→ 这几个问答**合成一篇文件**。

通用要求：

- 先去重、按序号从小到大。
- 分开模式：先检查完所有目标文件名，再开始写；任何一篇同名冲突 → 整批停下问，一篇都不要写，避免写了一半。
- 合并模式：把这几个问答按序号顺序依次排进同一篇；检查那一篇文件名，冲突 → 停下问。
- **合并要「整合」不要「堆叠」**：把这几问当成一个整体——先找出它们的共同主题和先后关系，再按「总纲 → 为什么 → 好处/代价 → 判断标准」这类结构重新组织成一篇连贯文章；保留关键结论、数字、代码、易错点，但不要原样平行堆几段问答。

## 输出

写完后回：

单篇 / 分开模式：

```
已存：D:\vault\问题.md（1240 字）
```

分开批量：

```
已存 3 篇：
- D:\vault\A.md（820 字）
- D:\vault\B.md（610 字）
- D:\vault\C.md（940 字）
```

合并模式：

```
已存（合并 3 问）：D:\vault\...等3问.md（2100 字）
```

就这些。不加开场白、不加评价、不问「还要不要做别的」。

需要确认时（越界路径、同名冲突、序号越界），只发那一句问题 + 必要的表或路径，不要夹带别的话。

## 边界情况

- **本会话一个问题都没有** → 「本会话还没有提问，没有可存的内容」
- **序号越界** → 贴出当前表 + 一句「表里只到 Q6」
- **用户给的地址是个已存在的文件、但没写 .md** → 当目录处理，别把文件覆盖成目录
- **同一批里有两篇会撞名**（例如两个问题的标题一样）→ 按顺序第一个用原名，后面的加 `-2`，并在输出里说明

## 反例

用户：`/conclude`

错误：<br>
「好的！我来帮你整理这次对话中最后一个问题。首先……」→ 开场白，删掉。

正确：直接写文件，回一行「已存：…（N 字）」。

用户：`/conclude 2`

错误：<br>
把 Q2 的回答压缩成三条要点，丢掉推导过程。

正确：保留原来的小标题和推理结构，只删「好的」「希望有帮助」这类。

用户：`/conclude 9 我的笔记`，但表里只有 Q1–Q6

错误：<br>
自作主张改成存 Q6。

正确：贴出表 + 「表里只到 Q6，9 没有对应的问题」。
