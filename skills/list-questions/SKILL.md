# /list — 会话提问索引

用户发 `/list` 时，把**本次会话**中他问过的问题整理成一张表。

这是索引，不是总结：不要评价问题、不要补充答案、不要建议下一步。

> 配套：本 skill 常与 `conclude` 一起用（`/list` 出表 → `/conclude 3` 按表中编号存档）。单独使用也成立。

## 触发条件

- 用户**只发送** `/list`，或 `/list` 后面跟一个关键词
- 大小写都算（`/list`、`/LIST`）
- 行首的 `/list` 才算；正文里提到 "/list" 不算

## 输出格式

只有一张表：

```markdown
| # | 问题 |
|---|---|
| Q1 | …… |
| Q2 | …… |
```

表格之外最多一行统计，例如 `共 6 问`。

**不要**：开场白、"好的""以下是"、解释规则、结尾提问、分点说明。

## 纳入与排除

**纳入**——真正在问"是什么 / 为什么 / 怎么做 / 能不能 / 有什么区别"的句子。

**排除**：

- 纯操作指令（"存进 obsidian"、"换成 C 盘"、"写进去"、"改一下"）
- 补充信息的陈述（"我的笔记在 Obsidian 仓库里"）
- 对上一句的确认（"对"、"好"、"可以"）
- 触发命令本身（`/list`）
- 格式微调指令（"不要那一列了"）

判断方法：这句话如果单独拿出来，读的人会知道"他想知道某件事"吗？会，就纳入；不会，就排除。

## 写法

"问题"列必须**脱离对话上下文也能看懂**。

- 把口语改写成书面问句："我如何使用" → 保持；"那我呢" → 不行，要写清楚在问什么
- 不照抄带情绪的原文
- 长度控制在 30 字以内

## 编号

- 从 Q1 开始，按提问先后顺序
- **每次重建整张表**，不是追加；重排后编号可能变化
- 表格行序等于提问顺序（最早的在上）

## 范围

只覆盖**当前会话**。

不同会话各自一张表，不合并、不继承、不去读其他会话的记录。用户没要求就别去翻历史文件。

## 过滤词

用户写 `/list 部署` 时，只保留问题文本里包含该关键词的行，编号不变（保留原始 Q 号，不重排）。

匹配不上就输出空表 + 一行 `没有匹配「部署」的问题`。

## 边界情况

- **会话刚开始就问**：输出空表 + `共 0 问`
- **全是操作指令**：同上，不要硬凑
- **用户已经改过格式**（比如要求去掉编号列）：在**当前会话内**沿用新格式；不要因为本文件写了两列就改回去

## 反例

用户：`/list`
错误回答：
> 我来帮你整理一下这次对话中的问题。以下是……

正确回答：直接给表格，上面那句话一个字都不要。

用户：`/list`
错误回答：表格后面加"需要我针对哪个问题展开吗？"
正确回答：表格 + `共 6 问`，到此为止。
